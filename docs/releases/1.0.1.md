# Relay 1.0.1

Relay 1.0.1 is a compatibility and catalog patch for the 1.0 line. It keeps the same five provider lanes, model picker, cross-provider subagents, local-model support, usage dashboard, and blue interface.

## Downloads

- **Windows 10/11:** `relay-1.0.1-windows.zip`
- **Linux:** `relay-1.0.1-linux.tar.gz`
- **macOS 13+:** `relay-1.0.1-macos.tar.gz`
- **Verification:** `SHA256SUMS.txt`

These remain unsigned portable archives for users who already have Python 3.11 or newer and Codex installed. They are not signed or notarized `.exe`, `.msi`, `.pkg`, `.dmg`, or package-manager installers.

## Fixes

- Windows `model_catalog_json` updates now preserve backslashes literally, so the edited Codex configuration remains valid TOML.
- Every generated catalog entry now includes the instruction metadata Codex requires. Non-OpenAI routes use direct tool mode and disable Responses-lite so Codex can load Claude, Kimi, OpenCode, and local models correctly.
- Release verification now rejects a generated catalog if any route is missing `base_instructions` or `model_messages`.
- The installed Windows build was exercised with a live Codex request through the default Relay route.

## Model catalogs and Codex linking

- **Add model** now loads live provider lists on open and provides a refresh control, search across every provider, and a large scrollable menu. During the Windows release check, the provider API returned 12 OpenAI, 14 Claude, 6 Kimi, and 82 active OpenCode entries (114 live catalog entries); the picker listed 116 total entries because it also retains two configured OpenCode routes not present in that live snapshot. Provider results remain dynamic and can change.
- OpenCode entries marked deprecated are excluded. Catalog failures retain the previous successful list when available, otherwise fall back to the shipped catalog, and never expose bearer tokens or API keys.
- **Connections → Codex on this PC** now has a one-click **Link Codex on this PC** action. It updates only Relay's default model, catalog path, `mixed` provider, desktop reasoning choices, and agent enablement. Existing projects, plugins, providers, and credentials are preserved, and a timestamped `config.toml` backup is created.
- Codex does not need to restart for the router to reload the catalog. Open a new Codex conversation after linking so the updated picker is selected.

## Upgrade

1. Download the archive for your operating system.
2. Stop only the Relay manager and router processes you intend to replace. Codex can stay open.
3. Run the installer with `--configure-codex` using the same Codex home. It retains timestamped configuration and source backups.
4. Start the updated router, then the Relay manager.
5. If the desktop Codex process was open when its catalog was first changed, start a new Codex conversation. A full desktop restart is only needed if the application cached an earlier invalid catalog error.

There are no settings-schema or credential migrations in this patch. Existing Relay preferences, connected accounts, and usage records are preserved.

## Verification

The release workflow requires Python tests, source and credential validation, a production build, rendered UI checks, native Windows/Linux/macOS archive launch and installer tests, tag/version consistency, and post-publication SHA-256 verification.

## Known limits

- Provider OAuth flows, model IDs, quotas, allowance endpoints, and tool compatibility can change without provider notice.
- Claude OAuth and subscription eligibility remain controlled by Anthropic.
- Hosted web search and large connected-app namespaces remain OpenAI-only.
- Local model quality, context size, image support, and tool calling depend on the local server and model.
- Relay archives are portable and unsigned; native signed installers, automatic transactional rollback, and a dedicated uninstaller are post-1.0 work.

Relay is an independent project and is not affiliated with or endorsed by OpenAI, Anthropic, Kimi, or OpenCode.
